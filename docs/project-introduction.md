# DevPilot 正式项目介绍

## 正式介绍

DevPilot 是一套面向学生开发团队与小型技术团队的 GitHub 项目协作与 AI 工程助手。

项目以团队真实 GitHub 仓库为数据来源，通过 Webhook 和 GitHub API 同步 Push、Issue、Pull Request、Review 等研发活动，并在本地建立工作空间、项目、成员、任务、通知、审计和知识库模型。系统将分散的仓库活动、任务状态、会议决策与项目文档整合为统一项目上下文，帮助成员快速了解当前进度、责任分配、风险项和历史决策。

DevPilot 不替代 GitHub，而是解决 GitHub 原生协作之外的团队上下文问题：项目活动难以汇总、任务和代码缺乏关联、周报依赖人工整理、新成员理解项目成本较高，以及 AI 助手无法在权限边界内安全调用真实项目工具。

后端采用模块化单体设计，以工作空间和项目权限为安全边界，围绕 Webhook 可靠接收、事件幂等、异步处理、失败重试、定时对账、状态机、通知和审计构建完整工程链路。后续增加知识库与 Agent，使 Agent 能查询项目状态、总结 PR、从会议纪要生成任务草案，并在人工确认后调用正式业务服务创建 Issue 或更新任务。

它不是孤立聊天机器人，也不是仅供展示的 CRUD 系统，而是一套可接入真实仓库、由真实团队持续使用和迭代的研发协作基础设施。

## 一句话介绍

> DevPilot 是一个连接 GitHub 仓库、团队任务、项目知识与 Agent 工具的智能研发协作平台。

## 30 秒面试介绍

> 我在参与多人开发和挑战杯项目时，发现需求、会议纪要、任务和 GitHub 提交比较分散，团队成员很难快速知道项目当前进度，因此开发了 DevPilot。系统通过 GitHub Webhook 同步 Push、Issue 和 Pull Request，使用签名校验保证来源可信，使用 Delivery ID 和数据库唯一约束保证事件幂等，事件落库后再异步处理并生成项目活动时间线；同时设计了工作空间权限、任务状态机、通知、审计和失败补偿。后续我增加项目知识库与 Agent 工具调用，让 Agent 能在当前用户权限内总结进度、拆分需求，并经人工确认后创建 GitHub Issue。

## 简历描述模板

### DevPilot — GitHub 项目协作与 AI 工程助手

基于 Spring Boot 与 Java 21 设计模块化单体架构，面向学生开发团队提供工作空间、项目、仓库接入、任务协作与项目知识管理。通过 GitHub Webhook 实时同步 Push、Issue、Pull Request 等事件，采用 HMAC-SHA256 验签、Delivery ID 唯一约束、事件状态机和异步重试保证同步可靠性；通过工作空间级 RBAC、资源归属校验和操作审计保护私有项目数据；构建任务状态机、截止提醒、Review 超时升级和站内通知，并引入 Agent Tool Calling，使 Agent 在继承用户权限的前提下查询项目、生成任务草案，经人工确认后执行受控写操作。

> 简历只保留真正实现并能够解释的内容。

## 真实使用计划

初期接入黑马点评仓库、DevPilot 自身仓库和挑战杯团队仓库。记录接入仓库数、成员数、Webhook Delivery 数、重复事件拦截数、失败重试数、通知数、Agent 提议数和根据用户反馈完成的迭代数。

不要伪造百万用户。对于学生项目，“6 名真实成员持续使用一个月并完成三轮迭代”更可信。
